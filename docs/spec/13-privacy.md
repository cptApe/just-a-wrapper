# Who can do what

Work is private to the member who created it, including from owners and admins. Sharing is an explicit act. A workspace has one shared place in the Library, the `/Team` folder. Only a task's creator controls the task, even after sharing it. Roles (`owner`, `admin`, `member`, in [`src/lib/workspace-role.ts`](../../src/lib/workspace-role.ts)) govern workspace settings, never access to private work. The reason is in [decision 0020](../decisions/0020-private-by-default-teams.md).

Every check below starts from a caller. [`src/lib/caller.ts`](../../src/lib/caller.ts) resolves it and joins the current member row and a live workspace, so a removed member fails the same way everywhere ([decision 0025](../decisions/0025-one-caller-resolver.md)). Role gates use `resolveCaller(headers, { atLeast })` or `roleIsAtLeast`.

## Rules the table cannot hold

- **Blocked actions never run unattended.** A task run with Skip confirmations has no person present. There, a connected-app call whose actions the gate cannot read (the Tool Router workbench or sandbox, a batch input it does not recognise, any meta-tool off the read-only list) is refused while the creator has Block on any app action. With a person present, such a call asks for approval while the member has any Block, and otherwise follows the session mode, as other unknown calls do. See `readGatedCall`, `isUnattended` and `decideOpaqueCall` in `src/features/permissions/lib/resolve.ts`, applied by `resolveToolGate`, and [decision 0033](../decisions/0033-what-an-agent-may-do-without-a-person.md).
- **Remembered approvals name exact actions.** "For this task" is stored under each action a call runs, never under a meta-tool that can run actions (`taskApprovalNames` and `rememberToolApprovalForSession` in `src/features/permissions/api/approval-scopes.ts`).
- **One decider per kind of tool.** Built-in tools run through `decideBuiltinToolGate` in the dispatcher and on the Tools page. Connected-app actions run through `decideConnectedAppGate`. There are no wildcard policy rows; `tool_permission_exact_tool_check` refuses them.

- **Custom tools run as the creator.** Before running a batch, the dispatcher checks that the creator can still act. When they cannot, each call gets a `FORBIDDEN` tool result instead of running. See `prepareCustomToolDispatchGates` and `dispatchCustomTool` in `src/features/tools/api/dispatch.ts`.
- **Demotion ends read-write memory tasks.** Managed Agents fixes a session's memory access when the session is created. A creator who drops below admin on a task that mounted workspace memory read-write must start a new task. `sessionActorRefusal` enforces this.
- **Browser sign-ins belong to one member.** Each member has their own browser context (`ensureMemberBrowserContext` in `src/features/tools/api/browser-contexts.ts`). Member removal and workspace cleanup keep the context ID in `browserContextCleanupIds` until the provider confirms deletion. Readers of a shared task never get the live browser view: `GET /api/sessions/[id]/browser` requires a write grant through `authorizeBrowserControl`.
- **Removing a member.** `revokeMemberWorkspaceAccess` in `src/features/workspaces/api/revoke-member-workspace-access.ts` runs in one transaction. It moves the member's files outside `/Team` to trash. It also trashes their folders outside `/Team` and `/Chat uploads`, unless a folder holds a teammate's file. It revokes their file, folder and task links, cancels their tasks and hides their running task runs. It queues cleanup of their connected-app user, vault and personal memory store. Team files stay. Admins never see the removed member's private files.
- **Trash lasts 30 days.** Purging then deletes trashed files (`src/features/files/lib/trash-machine.ts`). The purge removes each file's stored bytes by its exact paths first and deletes the row only once they are gone (`purgeTrashRows` in `src/features/files/api/trash-transitions.ts`). The daily stored-file sweep then removes unreferenced bytes. Its brake stops the sweep when most unreferenced bytes sit under a workspace or account that still exists, which points to a bug; bytes whose workspace or account was purged never count toward it (`src/features/files/api/sweep-stored-files.ts`).
- **Files API mounts outlive failed deletes.** A file mounted into a session keeps its `session_file_mount` row until the provider deletes the upload, and trash purging skips files that still have one (`src/features/files/api/trash-transitions.ts`). Provider calls in the upload sweep use a ten-second timeout and no retries, and stop at the sweep deadline (`src/features/files/api/reconcile-anthropic-uploads.ts`). The sweep reports uploads it cannot match to a session for operator review and never deletes them, because a filename cannot prove which tenant owns a file.
- **Duplicate paths fail.** A Library path that matches more than one file is refused instead of picking one, so an agent never reads a private copy by accident (`src/features/files/api/library-operations.ts`).
- **Live events respect audience.** An event addressed to one member reaches only that member (`eventAudienceQuery` in `src/features/realtime/lib/audience.ts`).
